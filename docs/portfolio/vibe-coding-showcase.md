## 2. 可用于提交的作品简介

《魔导协议》是我的个人 AI 辅助开发练习，尝试把“训练—评估—迭代”转化为竖屏数值养成玩法。玩家调整日志配比和核心指令，预览训练成本，生成候选后手动应用，再通过自动战斗与失败报告判断方案是否有效。

我的工作重点是项目需求与迭代方向：提出画面简化、竖屏布局的要求，确定仓库文档、下载版本及策划材料的交付形式，并通过自然语言与 AI 编程助手协作推进。代码、样式、测试及文档包含 AI 辅助生成和修改，不将其表述为全部逐行独立手写。

目前作品是可运行的 Web 原型，覆盖训练、候选应用、自动战斗、评估和任务领奖流程，并非完整游戏。简短策划案补充了容量、成本与放置节奏模型；分档产率、逐卡养成和完整章节解锁仍属于待验证设计。

## 4. 约两分钟演示脚本

演示前先在同一个页面会话走完一次流程，确认日志和算力足够；正式录制时不要中途刷新。初始资源不足可等待战斗恢复，或重开页面重新演示，但这不是加载存档。

| 时间 | 操作 | 讲解重点 |
| --- | --- | --- |
| 0–20 秒 | 打开 `index.html`，完成或跳过引导，展示竖屏资源区与底部四栏 | “这是单页 Web 原型，重点是数值决策与流程。” |
| 20–40 秒 | 在作战页观察自动战斗，展开战报 | “战斗是游戏内数值模拟，不是调用真实模型推理。” |
| 40–65 秒 | 进入训练，选择低成本配置（如 SFT、1 轮），调整三路配比和核心指令 | 展示日志、算力、预计写入和容量预览；说明投入总量与配方的区别 |
| 65–85 秒 | 资源足够时执行训练，进入仓库查看候选并点击应用 | **生成候选不等于应用**；应用是玩家明确确认的步骤 |
| 85–105 秒 | 回到作战，观察新向量与战报；若失败，打开评估报告 | 失败报告给出下一次调整方向；若没有失败，不声称已展示失败案例 |
| 105–120 秒 | 展示已完成任务的手动领奖或蓝图导出，简述本人 / AI 分工及限制 | “没有存档与完整卡牌收集；扩展数值规则还需要验证。” |

录制可使用系统录屏工具，将文件上传到自己的视频或网盘平台后，把实际链接补到本说明；未录制前不要把脚本当作视频作品链接。直接提交现有下载试玩链接，也可满足“作品链接或演示”的形式。

## 5. 实现范围与技术说明

- **已实现：** 单页 HTML/CSS/JavaScript；三人自动战斗、战报与失败评估；三路训练配比；训练配置与成本预览；候选生成、手动应用；任务领奖；蓝图 JSON 导出。
- **原型简化：** 三人共享向量，固定基模展示，深度手动选择；固定 400 LOG/h，而非策划案分档产率。
- **尚未实现：** 存档、跨会话离线结算、独立卡牌养成、自由编队、完整地图解锁、抽取、蓝图导入。
- **不含真实模型训练：** DeepSeek、Kimi、MiniMax、SFT/DPO/RFT 与 Benchmark 选项属于游戏设定，不会联网执行机器学习任务。
- **验证边界：** 仓库 Node 测试是契约检查和部分运行时断言，不等于完整浏览器端到端测试。策划表中的等待时间是公式预测，不是玩家实测；未宣称留存或商业化成绩。
