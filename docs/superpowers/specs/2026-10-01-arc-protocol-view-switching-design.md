# 《魔导协议》视图切换与训练结果仓库设计

日期：2026-10-01

## 背景

当前原型将作战、模型仓库和后训练内容全部堆叠在一个长页面中，信息层级不清晰。需要保留现有战斗、训练可视化和攻击动画，同时把三个功能组织成同页视图切换。

## 目标

1. 主界面首先展示作战状态，而不是训练表单。
2. 模型仓库和后训练拥有独立视图，可通过顶部导航切换。
3. 仓库不仅展示 DeepSeek、Kimi、MiniMax 三个初始模型，也展示每次执行训练产生的训练结果。
4. 切换视图不停止战斗 tick，不改变战斗、训练或胜负数据。
5. 保持无存档、无抽卡、无远程资源和无网络模型 API。

## 视图结构

### 作战中

- 顶部资源指标：源质容量 P、五维已写入点、离线日志库存。
- 当前深度、敌方状态、我方三具素体状态。
- 当前协议摘要：训练配比、指令、当前聚焦模型/结果。
- Tick 战报与重新演算、清空战报操作。
- 每次攻击的投射物、命中反馈和伤害飘字保持不变。

### 模型仓库

分为两个区块：

1. 初始模型：DeepSeek、Kimi、MiniMax。
2. 训练结果：每次成功执行训练后生成一条不可持久化的运行时记录。

训练结果记录至少包含：

- 唯一 ID；
- 生成时间；
- 深度与容量；
- Bulwark / Weaver / Conductor 配比；
- 训练指令；
- 本次写入点数；
- 写入后的五维向量快照；
- 训练状态；
- 使用/聚焦操作。

仓库卡片可以将某条记录设为当前聚焦对象。聚焦只影响界面高亮和摘要，不修改战斗计算。

### 后训练

- 离线日志库存与预计可训练次数。
- 三个训练配比滑杆，合计 100%。
- 破阵 / 护卫 / 共鸣指令。
- 五维成长预览、50% 认知固化警戒线。
- 执行训练按钮和训练结果反馈。

## 数据流

- 页面初始化时创建空的运行时训练结果数组，不写入 localStorage、sessionStorage 或 indexedDB。
- \`executeTraining()\` 成功后，先按现有规则扣除日志并写入向量，再创建训练结果快照并加入仓库。
- \`renderModelRepository()\` 统一渲染初始模型和训练结果。
- \`setActiveView(view)\` 只更新当前视图标记、导航状态和可见性；不触碰 \`state.battle\`、\`state.vector\` 或战斗计时器。
- \`focusModel(key)\` 与训练结果的聚焦操作只更新 \`state.focusedModel\` / \`state.focusedTrainingId\`。

## 交互与视觉层级

- 顶部导航采用三个等宽标签：作战中、模型仓库、后训练。
- 当前视图使用高亮底色、边框和短下划线标记。
- 主界面减少训练表单和仓库卡片，优先呈现战斗状态。
- 仓库内初始模型和训练结果使用不同的标签颜色，避免用户误认为训练结果是固定模型。
- 训练结果卡片采用网格布局；窄屏时单列显示。
- 视图切换使用轻量淡入，不引入外部动画库。

## 边界与兼容性

- 不新增后端、网络请求、用户账号或持久化。
- 不改变 P(d)、C(d)、d1-d15、离线产出和战斗伤害公式。
- 不改变现有攻击动画接口、tick 日志和卡关报告。
- 没有训练结果时显示空状态，引导用户前往后训练。
- 刷新页面后训练结果清空，符合“不存档”要求。

## 验收标准

- 初次进入默认显示“作战中”，主视图不显示完整训练表单和仓库列表。
- 点击“模型仓库”只显示仓库视图，能看到三种初始模型和所有当前会话训练结果。
- 执行一次训练后，仓库新增一条训练结果卡片。
- 切换视图前后战斗 tick 继续推进，聚焦操作不改变伤害或胜负。
- 现有动画、训练成长、模型仓库契约测试继续通过，并新增视图切换与训练结果仓库测试。
