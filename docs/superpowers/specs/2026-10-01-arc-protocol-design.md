# 《魔导协议》单页原型设计

日期：2026-10-01

## 目标
制作一个无需构建工具、打开即玩的单页 Web 放置游戏原型，展示“离线收集 → 后训练 → 自动战斗 → 卡关评估 → 导出蓝图”的最小闭环。

## 视觉方向
采用“协议终端”视觉：石墨黑背景、骨白文字、青绿/琥珀/冷蓝三种日志色，等宽数字承载容量、伤害、tick 和时间。页面保持无插画、无卡牌美术、无装饰性背景图；用细边框、扫描线和状态标签表现系统感。唯一醒目的视觉签名是战斗区中央的“协议链路”连接线与伤害数字浮层。

## 信息架构
1. 顶栏：品牌、协议深度 d1–d15、源质容量 P、离线日志库存与收取状态。
2. 主战斗区：左侧 3 个我方素体方块，右侧 1 个敌方方块；显示血条、当前向量倾向、战斗阶段与 tick 战报。
3. 训练面板：Bulwark / Weaver / Conductor 三个配比滑杆，自动保持和为 100%；破阵 / 护卫 / 共鸣单选；执行训练与导出蓝图。
4. 诊断区：五维写入条、认知固化警告、卡关评估报告。

## 数值和交互约定
- 协议深度 d 仅支持 1–15。
- 源质容量：P(d)=100*1.15^(d-1)。
- 每点成本：C(d)=2*1.10^(d-1)。
- 三个训练滑杆总和固定为 100%，只写入 Bulwark / Weaver / Conductor；Vanguard 与 Marksman 在本原型中保留为可见但为 0 的维度。
- 训练点数由当前离线日志库存和剩余容量共同限制。
- 离线日志：使用 Date.now() 计算距离上次收取的小时数，产率 400/小时，最多 8 小时；不使用 localStorage，不做持久化。
- 单维写入超过 P*50% 时显示“认知固化”，本维收益 +20%，面对克制标签整体 -15%。
- 战斗按 1 秒 tick 运行，追加文字战报，并显示短暂的飘伤害数字。
- 卡关时生成覆盖率、伤害溢出、存活缺口、建议四项报告。
- 导出蓝图复制 JSON，至少包含协议深度、三维配比与指令。

## 成功标准
- 直接打开 HTML 即可使用，无外部依赖。
- 三个滑杆任何变化后总和仍为 100%。
- 执行训练后五维写入、职业标签和战斗行为发生可见变化。
- 自动战斗能明确显示胜利与卡关，卡关报告可读且可指导下一次配比。
- 离线库存按时间计算且不超过 8 小时产出。
- 警告、复制反馈、按钮和滑杆具备可见焦点与基本响应式布局。
