# 后训练多候选结果与自主选择实施计划

> 日期：2026-10-01

## 目标

让后训练连续生成多个候选结果，并在模型仓库中由玩家自主选择应用；生成和应用严格分离，应用不重复扣除资源。

## 约束

- 保持单页原生 HTML/CSS/JavaScript；
- 不使用任何持久化 API；
- 保留现有战斗、动画、任务、引导和资源规则；
- 训练失败不扣 LOG / C；
- 只允许一个活动训练结果，但旧候选全部保留。

## Task 1：契约测试（RED）

- 新增 tests/training-selection.test.mjs；
- 检查活动结果状态、候选快照、应用函数、仓库应用按钮、应用不重复扣费的代码契约；
- 先运行并确认因功能缺失而失败。

## Task 2：训练结果状态与生成逻辑

- 增加 activeTrainingId:null；
- executeTraining() 改为生成 candidateVector 并追加候选，不覆盖 state.vector；
- 结算卡明确显示“候选结果已生成，尚未应用”；
- 连续训练结果使用唯一 id 并保留历史。

## Task 3：仓库选择与应用

- 增加 applyTrainingResult(id)；
- 仓库卡动态展示“当前应用/候选结果”；
- 增加“应用到当前协议”按钮，并绑定点击事件；
- 应用后同步深度、配比、指令和训练配置，刷新预览与战斗；
- 应用操作不触发资源扣除。
